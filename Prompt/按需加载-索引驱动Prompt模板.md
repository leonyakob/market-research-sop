# 按需加载：索引驱动的模块启动 Prompt

> **设计目标**：通过元数据索引实现"先判断、后加载"，大幅减少token消耗，避免上下文臃肿

---

## 适用场景

当你在以下场景时，使用本Prompt：
- 要设计新的SOP模块
- 需要引用上游模块的输出
- 不想一次性加载所有上游完整文档

---

## Prompt 模板（复制到新session使用）

```markdown
# 【索引驱动】模块启动指令

## 任务目标
设计/优化 **{模块编号} {模块名称}** SOP

## 执行原则
1. **先读索引，不读全文**：首先读取模块元数据索引，理解依赖关系
2. **按需加载，精准引用**：只在需要具体细节时，才读取上游模块的特定章节
3. **接口优先，内容次之**：优先关注模块间的输入输出接口，而非完整内容

## 必须首先读取的文件
按顺序执行：
1. `~/github/market-research-sop/AGENTS.md`（项目规则）
2. `~/github/market-research-sop/.sop/config/module-index.yaml`（模块元数据索引）★最重要
3. `~/github/market-research-sop/交付文档/SOP-通用模板.md`（模板）

## 索引使用方法

### Step 1: 理解当前模块
从索引中获取：
- 模块类型（数据研究型 / 对比/判断型）
- 上游依赖列表
- 下游输出目标
- 本模块的可消费输出定义

### Step 2: 判断加载策略
根据当前任务阶段选择加载方式：

| 任务阶段 | 加载策略 | 示例 |
|---------|---------|------|
| 框架设计 | 不加载上游文档，只依赖索引中的依赖关系 | 设计1.5的机会筛选框架 |
| 接口定义 | 按需加载上游的 `export_sections` | 定义1.5与2.1的接口 |
| 内容填充 | 按需加载上游具体章节 | 验证竞争机会清单 |
| 验证测试 | 按需加载相关章节进行交叉验证 | 检查机会-定位映射 |

### Step 3: 按需加载上游内容

**只在以下情况加载上游文档**：
- 需要查看上游模块的具体输出格式
- 需要验证上游输出是否符合本模块输入要求
- 需要提取上游模块的特定章节内容

**加载方式**：
```
不要：读取 ~/github/market-research-sop/交付文档/1.1-行业研究SOP.md
要：   根据索引中的 export_sections 读取特定章节
```

## 你的工作流程

1. **先读取索引文件**（module-index.yaml），理解模块依赖图谱
2. **根据当前任务判断**：需要了解上游的哪些方面？
3. **只加载必要的上游章节**，不读全文
4. **优先设计接口和框架**，内容细节后续补充
5. **随时可以通过索引查询**其他模块的元数据，无需全部加载
```

## 使用示例：设计1.5机会分析

### 传统方式（高token消耗）
```
用户：设计1.5机会分析SOP

AI读取：
- 1.1-行业研究SOP.md（593行）
- 1.2-竞争分析SOP.md（xxx行）
- 1.3-消费者研究SOP.md（xxx行）
- 1.4-趋势分析SOP.md（xxx行）
- 然后才能开始设计1.5

Token消耗：~4000-6000 tokens
```

### 索引驱动方式（低token消耗）
```
用户：设计1.5机会分析SOP

AI读取：
- module-index.yaml（元数据索引）
- 从索引得知：
  - 1.5类型：对比/判断型
  - 上游：1.1, 1.2, 1.3, 1.4
  - 1.5需要：industry_opportunities, competitive_opportunities 等
  - 1.5输出：priority_opportunities, opportunity_positioning_map 等

只有在需要查看具体输出格式时，才按需加载1.1的"行业机会点与风险点"章节

Token消耗：~800-1200 tokens（节省70%+）
```

## 进阶：章节级按需加载

当确实需要查看上游模块的具体内容时，使用章节级加载：

### 方法
1. 先读取上游模块的前100行（获取目录结构）
2. 根据目录结构定位需要的章节
3. 使用 `read offset=X limit=Y` 读取特定章节

### 示例
```
需要：查看1.1的行业机会点输出格式

步骤1：读取前100行，找到"机会与风险"章节位置
步骤2：发现章节在offset=450处
步骤3：read filePath=".../1.1-行业研究SOP.md" offset=450 limit=80
步骤4：只获取了需要的章节，而非全文
```

---

## 注意事项

1. **索引是源头**：永远先读索引，理解依赖关系后再决定加载策略
2. **延迟加载**：只在需要具体细节时加载完整内容
3. **接口优先**：设计阶段关注输入输出接口，而非完整内容
4. **可回退**：如果需要完整内容，随时可以完整加载上游文档
