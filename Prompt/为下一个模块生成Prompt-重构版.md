# 为下一个模块生成 Prompt（重构版｜适配新版SOP设计体系）

## 当前任务定义
你现在的任务不是撰写 SOP，也不是执行某个具体品牌项目的研究任务。

你当前的任务是：

1. 判断品牌策划全案 SOP 项目当前已完成到哪个模块；
2. 推导下一个应启动的模块；
3. 判断该模块属于哪一种 Prompt 模板类型；
4. 为该模块生成一份可直接用于新 session 的启动 Prompt；
5. 将生成结果写入 `~/github/market-research-sop/Prompt/` 目录。

注意：
你生成的是 **“用于设计下一个 SOP 模块的启动 Prompt”**，不是下一个模块的 SOP 内容本身。

---

## 核心边界（必须遵守）
本任务服务于 **SOP 设计**，不是 **SOP 执行**。

因此你生成的 Prompt 必须围绕以下内容展开：
- 模块职责
- 章节结构
- 工作步骤
- 数据/资料要求
- 输入输出接口
- 判断标准
- 质量检查标准
- 与上下游模块的衔接关系

不得将 Prompt 写成针对某个具体品牌/具体产品/具体项目的执行需求访谈。

以下内容不应成为生成 Prompt 的核心访谈对象：
- 某个具体品牌是谁
- 某个具体产品是什么
- 某次项目的具体目标人群是谁
- 某次项目要研究哪些具体竞品
- 某次项目采用哪组具体样本

这些属于未来“按 SOP 执行项目”时才需要确认的信息，不是当前“SOP 设计”阶段的核心输入。

---

## 模块顺序判断基准
品牌策划全案模块顺序，唯一以以下文件为准：

`~/github/market-research-sop/交付文档/1-品牌策划全案SOP框架.md`

## 完成状态识别规则
你必须通过以下方式判断当前进度：

1. 读取 `~/github/market-research-sop/交付文档/` 目录中的文件名；
2. 仅根据 SOP 主文件文件名判断哪些模块已完成；
3. 不以文件内容是否完整作为完成判断依据；
4. 将已有文件名与框架文件中的模块清单逐一对照；
5. 判断当前已经完成到哪个模块；
6. 再推导出下一个模块。

注意：
- 当前阶段只处理“市场研究”模块范围（1.1 ~ 1.5）
- 不要跨阶段推导到 2.x 及以后，除非用户后续明确扩展范围

## 当前阶段的模板分类规则
当前仅适用于“市场研究”大模块。

### 一、数据研究型
适用于：
- 1.1 行业研究
- 1.3 消费者研究
- 1.4 趋势分析

### 二、对比/判断型
适用于：
- 1.2 竞争分析
- 1.5 机会分析

你必须先判断下一个模块属于哪一类，再生成对应的实例 Prompt。

---

## 生成实例 Prompt 时的结构要求
你生成的新 Prompt 必须是一个可直接用于新 session 的完整启动 Prompt，并且必须包含以下结构：

1. 任务背景
2. 当前任务属于“SOP设计”而非“项目执行”的说明
3. 模块定位
4. 角色说明（Prometheus）
5. 必读文件
6. 阅读重点
7. 执行要求
8. 基础确认项
9. 模块专属确认项
10. 输出目标
11. 启动方式

---

## 生成实例 Prompt 时的提问机制要求
生成出来的实例 Prompt，必须符合以下提问规则：

1. 所有关键确认问题优先采用 **选项式提问**；
2. 不要要求用户进行大段输入；
3. 若选项无法完全覆盖，再允许用户补充一句简短说明；
4. 必须区分：
   - **基础确认项**：同类型模块共用
   - **模块专属确认项**：仅适用于当前具体模块
5. 不得把所有模块都写成同一套完全相同的问题；
6. 模块专属确认项必须根据当前模块编号切换。

---

## 数据研究型实例 Prompt 生成规则
如果判断下一个模块属于“数据研究型”，则生成的 Prompt 必须满足：

### A. 共用基础确认项应覆盖
- 模块主要职责
- 与前序模块关系
- 标准内容组织方式
- 核心输入类型
- 工作流程粒度
- 标准输出形式
- 通用方法与项目变量的处理方式
- 数据获取设计粒度
- 质量检查重点
- 与通用模板的关系

### B. 模块专属确认项必须按模块编号切换
#### 若为 1.1 行业研究
专属确认项应围绕：
- 行业研究重心
- 标准章节组织方式
- 行业边界定义是否固定
- 市场规模/增长判断是否固定输出
- 是否为 1.2 预埋接口
- 行业研究质量检查重点

#### 若为 1.3 消费者研究
专属确认项应围绕：
- 消费者研究重心
- 标准输出类型
- 分层方法是否固定
- 购买决策链路是否固定
- 后续模块服务重点
- 消费者研究质量检查重点

#### 若为 1.4 趋势分析
专属确认项应围绕：
- 趋势识别重心
- 标准章节组织方式
- 是否区分短中长期趋势
- 是否设置伪趋势过滤
- 后续模块服务重点
- 趋势分析质量检查重点

---

## 对比/判断型实例 Prompt 生成规则
如果判断下一个模块属于“对比/判断型”，则生成的 Prompt 必须满足：

### A. 共用基础确认项应覆盖
- 模块主要职责
- 与前序模块关系
- 标准内容组织方式
- 核心输入类型
- 比较/判断框架粒度
- 标准输出形式
- 通用框架与项目变量的处理方式
- 标准结论形式
- 质量检查重点
- 与通用模板的关系

### B. 模块专属确认项必须按模块编号切换
#### 若为 1.2 竞争分析
专属确认项应围绕：
- 分析重心
- 标准组织方式
- 比较对象组织方式
- 比较维度
- 是否固定竞争分组/竞争地图
- 后续模块服务重点
- 竞争分析质量检查重点

#### 若为 1.5 机会分析
专属确认项应围绕：
- 分析重心
- 标准组织方式
- 是否固定机会筛选标准
- 标准结论形式
- 是否明确机会来源对应关系
- 后续模块服务重点
- 机会分析质量检查重点
