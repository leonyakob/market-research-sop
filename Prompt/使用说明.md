# 四份 Prompt 使用说明

## 一、这四份 Prompt 分别是做什么的

### 1. 系统总控 Prompt
用途：
- 规定整个闭环 Prompt 系统的工作边界
- 让 OpenCode 明确当前任务是“品牌策划全案 SOP 设计”，不是某个品牌项目执行
- 约束它如何识别当前进度、如何判断下一个模块、如何选择对应模板

你可以把它理解为：
> 整个 Prompt 体系的“总规则”和“调度中枢”。

---

### 2. 数据研究型模板 Prompt（重构版）
适用模块：
- 1.1 行业研究
- 1.3 消费者研究
- 1.4 趋势分析

用途：
- 用于启动“数据研究型”模块的 SOP 设计
- 引导 OpenCode 通过结构化选项确认模块目标、输入、步骤、输出、判断标准和质检方式

你可以把它理解为：
> 数据研究类模块的通用启动模板。

---

### 3. 对比判断型模板 Prompt（重构版）
适用模块：
- 1.2 竞争分析
- 1.5 机会分析

用途：
- 用于启动“对比 / 判断型”模块的 SOP 设计
- 更强调比较维度、判断逻辑、筛选标准、结论输出方式

你可以把它理解为：
> 对比分析类模块的通用启动模板。

---

### 4. 为下一个模块生成 Prompt（重构版）
用途：
- 当你完成当前模块后，触发 OpenCode 自动判断“下一个应该写哪个模块”
- 自动为下一个模块生成一份可直接开新 session 使用的 Prompt
- 将生成结果保存到 `~/github/market-research-sop/Prompt/` 目录

你可以把它理解为：
> 闭环衔接器，用来把“当前模块”平滑推进到“下一个模块”。

---

## 二、最核心的使用原则

### 原则 1：每次开新模块时，至少要带上 2 份 Prompt
固定组合如下：
- **系统总控 Prompt**
- **对应类型的模板 Prompt**

也就是：
- 做 1.1 / 1.3 / 1.4 时：
  - 系统总控 Prompt
  - 数据研究型模板 Prompt
- 做 1.2 / 1.5 时：
  - 系统总控 Prompt
  - 对比判断型模板 Prompt

---

### 原则 2：生成“下一个模块 Prompt”时，要用 Prompt 4
当你完成一个模块后，如果你希望系统自动衔接下一个模块，就在新一轮调用时使用：
- 系统总控 Prompt
- 为下一个模块生成 Prompt（重构版）

然后输入触发语：

```text
为下一个模块生成 Prompt
```

只有当你手动输入这句话时，系统才应该执行“识别下一个模块并生成 Prompt”的动作。

---

### 原则 3：判断进度只看文件名，不看文件内容
这个体系的闭环逻辑不是通过读取 SOP 正文内容判断进度，
而是通过以下两项：
- `交付文档/1-品牌策划全案SOP框架.md`
- `交付文档/` 目录下已有 SOP 文件的文件名

也就是说：
- 框架文件负责定义完整模块顺序
- 已有文件名负责定义哪些模块已经完成
- 两者对比后，系统得出“下一个模块是谁”

---

## 三、标准使用流程

## 流程 A：开始设计某一个模块
适用于你已经明确知道当前要写哪个模块时。

### 第 1 步：判断该模块属于哪一类
- 如果是 1.1 / 1.3 / 1.4 → 数据研究型
- 如果是 1.2 / 1.5 → 对比判断型

### 第 2 步：在新 session 中引用对应 Prompt
推荐组合：

#### 做 1.1 / 1.3 / 1.4 时
- `系统总控Prompt.md`
- `数据研究型模板Prompt-重构版.md`

#### 做 1.2 / 1.5 时
- `系统总控Prompt.md`
- `对比判断型模板Prompt-重构版.md`

### 第 3 步：告诉 OpenCode 当前要启动哪个模块
例如：

```text
现在开始设计 1.4 趋势分析 SOP。
```

或者：

```text
现在开始设计 1.2 竞争分析 SOP。
```

### 第 4 步：按结构化选项完成确认
此时 OpenCode 会根据对应模板，围绕以下内容推进：
- 模块职责
- 输出目标
- 输入类型
- 步骤结构
- 数据 / 资料来源
- 判断标准
- 质检要求
- 模块专属确认项

你只需要按选项逐步确认，不需要从零写很长的说明。

---

## 流程 B：当前模块做完后，自动生成下一个模块 Prompt
适用于你希望形成“闭环接力”时。

### 第 1 步：确认当前模块对应的 SOP 文件已经存在于 `交付文档/`
例如当前已完成：
- `1.1-行业研究SOP.md`
- `1.2-竞争分析SOP.md`
- `1.3-消费者研究SOP.md`

### 第 2 步：在新 session 中引用这两份 Prompt
- `系统总控Prompt.md`
- `为下一个模块生成Prompt-重构版.md`

### 第 3 步：输入固定触发语

```text
为下一个模块生成 Prompt
```

### 第 4 步：OpenCode 自动执行以下动作
1. 读取 `交付文档/1-品牌策划全案SOP框架.md`
2. 识别市场研究模块的完整顺序
3. 扫描 `交付文档/` 中已有 SOP 文件名
4. 对比后判断哪个模块还没完成
5. 找出“下一个模块”
6. 判断这个模块属于哪种模板类型
7. 自动生成对应的启动 Prompt
8. 将结果保存到 `~/github/market-research-sop/Prompt/`

---

## 四、推荐工作方式

### 方式 1：手动启动当前模块
适合你已经知道下一步要写什么。

用法：
- 总控 Prompt + 对应类型模板 Prompt
- 直接说“现在开始设计 X.X 模块”

适用场景：
- 你已经决定本轮要写哪个模块
- 你不需要系统帮你判断顺序

---

### 方式 2：让系统自动衔接下一个模块
适合你希望按框架顺序持续推进。

用法：
- 总控 Prompt + Prompt 4
- 输入“为下一个模块生成 Prompt”

适用场景：
- 当前模块刚完成
- 你希望自动进入下一个模块
- 你不想手动改 Prompt

---

### 方式 3：生成后再开新 session
这是最推荐的闭环方式。

完整链路如下：
1. 当前模块设计完成
2. 使用 Prompt 4 生成“下一个模块 Prompt”
3. 到 `Prompt/` 目录中拿到新生成的 Prompt 文件
4. 新开一个 session
5. 引用：
   - 系统总控 Prompt
   - 新生成的模块 Prompt
6. 直接开始下一个模块

这个方式的好处是：
- session 更干净
- 模块切换更自然
- 不需要在旧 Prompt 基础上手动改很多内容
- 更符合你现在要的“模块设计接力”工作流

---

## 五、一个实际例子

假设当前 `交付文档/` 里已经有：
- `1.1-行业研究SOP.md`
- `1.2-竞争分析SOP.md`
- `1.3-消费者研究SOP.md`

而框架文件规定市场研究顺序是：
- 1.1 行业研究
- 1.2 竞争分析
- 1.3 消费者研究
- 1.4 趋势分析
- 1.5 机会分析

那么当你使用：
- `系统总控Prompt.md`
- `为下一个模块生成Prompt-重构版.md`

并输入：

```text
为下一个模块生成 Prompt
```

系统应该判断：
- 1.1、1.2、1.3 已存在
- 下一个未完成模块是 1.4 趋势分析
- 1.4 属于“数据研究型”
- 应生成一份“开启1.4趋势分析的Prompt.md”并写入 `Prompt/` 目录

然后你下次新开 session 时，就可以直接使用这份新 Prompt 开始 1.4。

## 七、推荐默认操作

1. 先判断模块类型
2. 带上：
   - 系统总控 Prompt
   - 对应模板 Prompt
3. 直接开始当前模块设计

### 完成一个模块后
1. 带上：
   - 系统总控 Prompt
   - Prompt 4
2. 输入：

```text
为下一个模块生成 Prompt
```

3. 去 `Prompt/` 文件夹拿新生成的 Prompt
4. 新开 session 继续

## 八、一句话记忆

这四份 Prompt 的关系可以简单记成：

- **Prompt 1**：管系统规则
- **Prompt 2 / 3**：管当前模块怎么开工
- **Prompt 4**：管下一个模块怎么接力

如果你要持续闭环推进，就按这个顺序循环：

```text
总控 + 模板开工 → 当前模块完成 → 总控 + Prompt4 生成下一个 Prompt → 新 session 继续
```
