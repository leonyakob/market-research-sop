## 为什么这些修改能解决 F1/F2 问题

1. **解决“有效内容修改”与版本历史更新的歧义**
   - 现在明确区分了两类场景：
     - 仅补版本历史：不触发 commit + push
     - 版本历史更新作为恢复/优化流程的一部分，且同时发生有效内容修改：随该次有效内容修改一起 commit + push
   - 这直接消除了此前“仅新增版本历史记录到底提不提交”的不闭合判断。

2. **解决第六章与第十二章的重复/冲突**
   - 第六章现在只保留同步总则与章节引用。
   - 第十二章成为唯一详细的 push 失败异常处理位置。
   - 这样保留了可读性，也避免两处细节将来漂移产生冲突。

3. **解决“先确认再修改”规则分散重复的问题**
   - 第五章新增了统一确认总则后，确认机制的判定、停止条件、默认值使用条件都集中在一个位置。
   - 第八章仅引用，不再重复展开，因此减少了散点重复和潜在措辞不一致。

4. **解决候选阶段执行说明的治理语义污染**
   - 第十四章现在明确声明只适用于候选稿评审/交接阶段。
   - 这保留了 Task-8 所需的交接限制，同时避免该说明被误读为长期项目治理规则的一部分。
