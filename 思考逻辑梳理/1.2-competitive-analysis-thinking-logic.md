## 二、核心设计原则演进

### 原则 1：SOP 的可重复性高于一切

**触发事件**：用户质疑"AI 自动适配维度"和"AI 自主选择新兴品牌"

**认知升级**：
```
初始想法：让 AI 智能判断 → 用户质疑 → 修正
核心认知：SOP 的核心价值是可重复、可预期
          不同大模型执行同一 SOP 必须得到一致结果
          任何"AI 自主判断"都是 SOP 的大忌
```

**设计原则**：
- 所有判断标准必须量化（阈值写死，不是模糊描述）
- AI 只是执行规则，不是做决策
- 可选维度触发条件 = 量化数字，不是"数据充足时"

### 原则 2：规划者先做专业筛选，不推给用户

**触发事件**：用户质疑"为什么列出 5 个框架让我选，而不是直接告诉我该用哪些"

**认知升级**：
```
错误做法：列出所有可能选项 → 让用户筛选 → 推卸专业判断责任
正确做法：先做专业筛选 → 只给适合的选项 → 说明排除理由
```

**设计原则**：
- 规划者的价值在于专业判断，不是提供菜单
- 每个排除项必须说明理由
- 用户确认的是方向，不是替你做专业决策

### 原则 3：先跑通，再优化（方案 C 的哲学）

**触发事件**：用户在 A（通用固定）、B（行业映射）、C（先通用后迭代）中选择 C

**认知升级**：
```
v3.0 的目标不是完美适配所有行业
v3.0 的目标是跑通流程，建立基础框架
后续迭代由实际使用反馈驱动，不是预设需求
```

**设计原则**：
- 避免过度设计
- 版本化迭代是内置能力，不是一次性完美
- 实证驱动 > 预设驱动

### 原则 4：决策顺序很重要

**触发事件**：
1. 用户指出"输出接口应等内部设计完成后再决定"
2. 我跳过维度方案确认就进入下一问题

**认知升级**：
```
错误：假设共识，跳过确认，进入下一问题
正确：每个决策必须明确确认后再继续
      内部设计完成 → 自然推导出输出接口
      不是先定义接口再设计内容
```

## 三、关键决策点与理由

| 决策点 | 选项 | 选择 | 核心理由 |
|--------|------|------|---------|
| 维度方案 | A通用/B映射/C迭代 | C | 先跑通，实证驱动迭代 |
| 竞品选择 | 手动/AI Top N/混合 | Top 5 + 用户指定 | 平衡覆盖度与用户控制权 |
| 分析维度 | 6必须+3可选 | 9个 | 覆盖品牌策划核心问题 |
| 分析颗粒度 | 深度/标准/精简 | 深度 | 每个维度独立成段，有数据+分析+洞察+启示 |
| 分析框架 | 5选N | 战略群组+对标矩阵+感知图 | 排除五力（1.1已做）、SWOT（适合分析自身） |
| 报告结构 | 初版4模块 | 修正后4模块 | 增加竞争趋势研判和竞争机会识别 |
| 可选维度触发 | 模糊描述 | 量化阈值 | ≥50条评价、≥2篇报道、公开融资 |
| 数据格式 | JSON/YAML | JSON | 通用标准，AI处理无障碍 |
| 输出接口 | 先定义/后定义 | 后定义 | 内部设计完成后自然推导 |
